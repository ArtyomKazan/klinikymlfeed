# Контекст проекта YML-фида Казанской клиники

## 20.11.2026 — Генерация фида для Яндекса

### Реализация

- `index.php` генерирует фид при каждом запросе. Корневой элемент `<shop version="2.0">` получает текущую дату и время Казани в формате `YYYY-MM-DD HH:MM`. Ответ отдаётся с типом `application/xml; charset=UTF-8`.
- В `<shop>` заданы название `ЛДЦ «Казанская клиника»`, компания «ООО Медворк», адрес сайта, контактный email и ссылка на логотип.
- `<doctors>` формируется из активных элементов инфоблока 33. Атрибут `id` получает `CODE`, ссылка ведёт на `/portfolio/CODE/`, а `internal_id` получает `ID`. Элемент `name` содержит полное значение `NAME`, `first_name` — второе слово. Фамилия берётся из `LAST_NAME` либо первого слова `NAME`, отчество — из `SECOND_NAME` либо третьего слова. Если отчества нет в обоих источниках, тег пропускается.
- В описании врача из `PROPERTY_TEXT_BLOCK` теги `<br>`, `</li>`, `</h4>` и `</p>` заменяются переносами строк. Остальные HTML-теги удаляются. В `experience_years` остаются только цифры из `PROPERTY_EXPERIENCE`.
- В `<clinics>` записаны адреса, контакты и общий логотип двух филиалов. `clinic_lushnikova` расположен на ул. Лушникова, д. 10, а `clinic_glushko` — на ул. Ак. Глушко, д. 21А. Для первой клиники `internal_id` и `company_id` равны 1, для второй — 2.
- `<services>` формируется из активных элементов инфоблока 65. Атрибут `id` имеет вид `service_ID`, `name` берётся из `NAME`, `internal_id` — из `ID`. Тег `gov_id` выводится при заполненном `PROPERTY_NUMBER`. Описание услуг и блок `<offers>` пока отсутствуют в выводе.
- Локальный `.htaccess` направляет запрос к `/local/yml_feed/yandex_yml.xml` в `index.php` без смены адреса. Правило требует Apache с `mod_rewrite` и разрешённым `AllowOverride` для папки. Если Nginx сам обрабатывает запрос к `.xml`, маршрут нужно настроить в Nginx.

### Технические решения

- Скрипт загружает пролог и модуль инфоблоков Битрикса. Общая выборка врачей и услуг проверяет флаг и даты активности, учитывает права чтения и пакетно загружает свойства элементов.
- Динамические поля экранируются для XML. HTML-разметка удаляется только из описания врача перед экранированием.

### Проверки и открытые задачи

- Синтаксис PHP и формирование XML проверялись локально на тестовых данных. Отдельно проверены разбор ФИО, условный вывод отчества и кода услуги, очистка описания и извлечение цифр стажа. Записи клиник и поля верхнего уровня проверены XML-парсером.
- На рабочей базе Битрикса нужно проверить выборку из инфоблоков 33 и 65 и доступность фида по адресу `/local/yml_feed/yandex_yml.xml`.
- Вывод описаний услуг и блока `<offers>` отложен.
